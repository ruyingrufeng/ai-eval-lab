# HANDOFF 2026-08-31 23:10：GLM 稳定性通过，20K 边界失败

## 结论

GLM-4.7 的四工具受控路线完成五轮稳定性回归，15/15 通过；限定 `verified_bounded` 继续成立。20K 严格 JSON 压力门禁失败，最大推荐边界仍保持既有 16,485 槽位 tokens，不扩展到 20K，也不取代 Qwen Ridge 的通用默认位置。

## 本轮证据

- 5 轮 × 3 任务，累计 15/15；进程均正常退出，精确落盘、外部 schema、会话绑定与 8086 请求全部通过。
- 十五次任务耗时 19.443–42.748 秒，中位数 31.062 秒；最大会话输入 1,480 tokens。
- 系统空闲内存最低 12%；五轮首尾 swap 已用量增加约 485.06 MB。
- 20K 目标实际提示 20,586 tokens、槽位 21,472 tokens，327.718 秒后只输出代码围栏起始符；进程返回 1，内容、裸 JSON、schema 均失败。
- 20K 前后 swap 从 14,586.62 MB 增至 14,891.44 MB，只剩约 468.56 MB；因此没有继续恢复 grep/glob，避免把资源压力与工具扩展混在一起。

## 评测器修复

`scripts/benchmark-glm47-dsh.py` 原先只把短任务成绩写入顶层 `all_task_grades_pass`，上下文失败仍可能让命令退出 0。本轮新增：

- `all_context_grades_pass`
- `all_grades_pass`
- 任一评分或绑定失败时非零退出
- 从 llama-server 日志记录 `server_max_prompt_tokens`

既有 15K 通过结果重新评分仍为通过；20K 结果现在正确返回失败。

## 当前使用边界

- 可用：真实 GLM、四工具 headless patch、串行文件任务、明确 JSON 契约、外部 schema。
- 不覆盖：20K 目标、grep/glob、bash、web、skill、subagent、workflow、并发和开放式研究。
- Qwen Ridge 仍是 dsh 通用配置默认；本轮设置已恢复并与评测前备份零差异。

## 下一步

先释放 swap 或重启形成干净资源基线，再单独新增 grep/glob 搜索任务门禁；不要同时扩大上下文。若搜索门禁通过，再考虑恢复 bash，并继续保持一次只增加一类工具。
