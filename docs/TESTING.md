# 测试与验收规范

每个候选项依次经过四个关卡：`discovered → installable → runnable → verified`。只有 `verified` 可以进入推荐栈。

每次测试任务结束必须生成可接替的交接记录：目标、时间、环境、命令/运行器、原始证据、已完成与未完成、当前服务/进程状态、停止条件、结论置信度和下一步。项目内保留任务交接文档，并按共享记忆协议追加 `07_agent交接日志.md`。

## 报告交付格式

- 从2026-08-14起，所有正式评测默认以自包含 HTML 作为主报告，文件名统一为 `report.html`；聊天摘要或 Markdown 不能替代 HTML 主报告。
- HTML 必须包含结论、指标定义、对比证据、限制和下一步，并在桌面与窄屏完成可读性验证。
- 报告数据先保存为可复核的 `artifact.json` 或等价机器结果，再由统一封装器生成 HTML；不得维护一套与数据脱节的手写图表。
- Markdown 可继续作为源报告、方法说明或交接附件，但交付入口必须指向 HTML。
- 敏感逐轮输出、授权素材和其他不宜分发的数据不得嵌入 HTML，只保留脱敏指标与结论；原文继续置于 Git 排除目录。
- 汇总报告存放在 `docs/reports/<report_id>/`，至少包含 `artifact.json`、`report.html` 和必要的来源说明。

不同内容类型不得共用一个笼统总分：文章、图片、视频、小说和数字人的硬门槛分别定义在 `benchmarks/content_type_test_plan.yaml`。

## 通用记录字段

- 工具/模型名称、版本或 commit、来源 URL；
- 权重格式、量化、文件大小与 SHA-256；
- 许可证、商用限制、可接受使用限制；
- 安装方式、Python/Node 版本、关键依赖；
- 冷启动时间、峰值内存、磁盘占用、运行温度/降频观察；
- 测试参数、随机种子、原始输出路径和复现命令；
- 结论、已知缺陷和决策日期。

## 性能、资源与并行

所有类别都必须分别测试单任务、同服务队列并发和跨服务共存负载。Apple Silicon 统一内存下，进程 RSS 不能替代系统物理内存、压缩内存、swap 与内存压力。完整字段、并行矩阵和停止条件见 `docs/PERFORMANCE_CONCURRENCY.md`。

至少报告：

- 冷启动、热运行、连续运行降速；
- 系统内存、memory pressure、压缩内存、swap 增量与 pageout；
- C0/C1/C2 队列吞吐、p50/p95、错误率和排队时间；
- 至少一个实际跨服务 X 场景的干扰系数；
- 测试停止原因与服务恢复情况。

## 文本模型

首轮指标：

- prompt processing tokens/s、generation tokens/s、首 token 延迟；
- 512 / 4K / 16K 上下文稳定性与峰值内存；
- 中文写作结构、指令遵循、长文一致性、JSON 输出、工具调用；
- 小说辅助的角色/时间线一致性（只使用中性合成题材测试）；
- 合法成人题材边界测试：成年人限定、指令遵循与禁止项阻断分别计分；
- 连续运行 10 次的错误率。

建议通过线：交互生成不低于 12 tok/s，10 次运行无崩溃，结构化输出成功率不低于 90%。质量采用盲评，不以单一公开榜单替代本机测试。

## 图像模型

- 512 与 768 分辨率的冷/热启动耗时、峰值内存；
- 中文和英文提示遵循、文字渲染、人物一致性、手部与构图；
- 固定 seed 的可复现性；
- 2/4 请求同时提交时的队列、总吞吐和 p95 延迟；
- 与本地 LLM、TTS 或视频渲染并行时的干扰系数；
- LoRA、ControlNet/IP-Adapter 或同类控制能力；
- NSFW 能力只记录“支持、受限或拒绝”，测试资产遵守 `SCOPE.md`。
- 人脸吸引力与自然度、身材比例与姿态、服装搭配和整体商业成片感；按 `docs/IMAGE_AESTHETIC_EVALUATION.md` 做匿名多 seed 盲评；
- 报告“每张合格图成本”和可直接使用率，不能只报告平均生成速度。

建议通过线：连续 10 张无 OOM/崩溃，API 可自动调用，工作流可导出且模型许可证满足目标用途；并行等级必须显式登记，未测并发不得声称支持并行生产。

## ASR / TTS

- ASR：中文 CER、英文 WER、实时系数、长音频漂移、时间戳；
- TTS：首包延迟、实时系数、中文可懂度、长文本稳定性、音频伪影；
- 声音克隆：仅授权样本，记录相似度的同时验证水印/标识与资产隔离方案。

## 视频 / 数字人

- 固定 3–5 秒、低分辨率测试片，记录每帧耗时和峰值内存；
- 动作一致性、闪烁、身份漂移、口型同步误差；
- 30 分钟连续批处理稳定性；
- 如依赖 CUDA 专用算子且无可靠 Metal 路径，直接标记为 `blocked_on_hardware`，不通过牺牲可维护性的补丁强行入选。

## 决策规则

总分建议：质量 35%、性能 20%、稳定性 15%、可控性 10%、许可证 10%、维护性 10%。任何一个硬门槛失败（无法离线、许可证不适用、重复崩溃、敏感资产无法隔离）均不得进入推荐栈。
