# 语言模型业务 Agent 工作流评测计划（2026-08-14）

## 结论

不再把自媒体写作、运营分析、行业调研、竞品洞察、产品调研、业务方案、PPT、网页和报告分别当成十几个孤立场景。它们收拢为三条端到端工作流；代码、数据计算和网页制作属于执行工具，PPT、报告和网页属于交付形式。

这样评测的对象不只是某一篇文章或某一张 PPT，而是模型能否持续完成“读资料 → 分析 → 产出 → 验证 → 修改 → 交付”的完整工作。

## 三条主工作流

### 1. 内容增长闭环

```text
资料与受众
  → 选题和内容策略
  → 自媒体写作与改稿
  → 运营数据分析
  → 下一轮实验计划
```

覆盖自媒体写作、运营分析，以及为内容服务的轻量产品/竞品洞察。交付物包括事实表、内容策略、文章、指标 JSON、运营复盘和下一轮计划。

### 2. 研究到决策闭环

```text
研究问题
  → 行业/竞品/产品证据
  → 比较与洞察
  → 方案选项和权衡
  → 业务方案
  → 管理层交付物
```

覆盖行业调研、竞品洞察、产品调研和业务方案。PPT、正式报告、网页报告只是最后一步可替换的交付格式，不单独重复测一遍内容能力。

### 3. 访谈到洞察闭环

```text
合成或脱敏访谈
  → 结构化整理
  → 主题编码
  → 原文证据映射
  → 不确定性与风险复核
  → 追问和报告
```

覆盖心理访谈辅助分析和其他定性用户研究。只评测整理、主题分析、风险识别和追问，不允许模型越权诊断或替代专业服务。

## 两个横向层

### 执行工具层

代码编写、数据清洗、指标计算、图表生成和网页实现不再作为孤立主场景。它们嵌入三条工作流，验证模型能否选择确定性工具解决具体业务问题。

### 交付物层

Markdown、PPTX、DOCX/PDF 和网页报告按需抽测。内容结论保持一致，只额外验收文件能否打开、数字是否一致、是否溢出、图表是否匹配来源以及网页能否构建和响应。

## 第一批：内容增长闭环

首批只跑一条完整工作流，不再跑三道互不相关的小题：

1. 阅读城市夜间公交资料和受众定位，建立事实表与内容策略；
2. 完成微信公众号文章初稿，并根据编辑意见修改；
3. 读取同一账号的四条历史内容数据，用程序重算完播率、互动率和关注转化；
4. 把文章策略与运营证据结合，形成下一轮四条内容的实验计划；
5. 输出文章、机器可读指标、运营复盘和执行计划。

单阶段可以单独定位失败，但最终按整条工作流判断是否可用。预计 35–55 分钟，单阶段最多 600 秒，整条链最多 60 分钟。

## 后续顺序

1. 内容增长闭环：先用 27B 建立基线，再横评满足 Agent 上下文要求的模型；
2. 研究到决策闭环：先固定资料包，之后增加实时网络检索 lane；
3. 访谈到洞察闭环：建立合成脱敏材料、安全信号和证据引用量表；
4. 每条工作流通过后，再抽测 PPTX、网页和 DOCX/PDF 交付。

## 报告方式

三条工作流分别给结论，不计算跨工作流总分。每条报告：首次完成率、阶段失败点、修订后通过率、事实/数字错误、上下文丢失、工具选择、总耗时、token、最佳用法和停止条件。
