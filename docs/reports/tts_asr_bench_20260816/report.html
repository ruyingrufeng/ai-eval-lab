1. ASR 横评 · 270s 中文长录音（4 引擎）

测试音频：edge-tts 合成的 100/200/500/1500 字 4 段中文拼接为 269.6s 长录音。faster-whisper / openai-whisper / SenseVoice 三类引擎 + 2 个模型尺寸，CPU int8 同基准对比。CER = 字符级编辑距离（去标点/空白），全文对齐算分。

关键观察：
  1. SenseVoice-Small 碾压胜出：CER 1.05%（接近真人水平），加载 24s，RTF 0.246 实时 4×。自带 emotion/event 标签（<|HAPPY|> / <|Speech|>）信息密度比 faster-whisper 高一档。
  2. faster-whisper base 的 28.66% CER 主要是"繁化误差"：模型把简中默认转繁中（"书房的灯"→"書房的燈"），不是字错。生产环境如果接受繁化输出，可降为 ~3%。
  3. 无尾段漂移：4 段（100/200/500/1500 字）CER 越往后越准（1500字段最低），VAD/分段稳定。
  4. 加载时间首跑 + cache 差异：faster-whisper small 首跑 472s（HF mirror 下载 ~500MB），cache 后 5s。SenseVoice 23.9s 含三个模型（SenseVoice + VAD + Punc）。

5. 踩坑记录（避免复用）

  1. 本机 HTTPS 代理 7892 已死：所有 curl/Python 请求走 HTTPS_PROXY=127.0.0.1:7892 → ConnectionRefused。对策：unset HTTP_PROXY HTTPS_PROXY; export NO_PROXY='*'; export HF_ENDPOINT=https://hf-mirror.com（Python requests 自动走）
  2. SenseVoice 输出有 emotion/event tags：<|zh|> <|HAPPY|> <|Speech|> <|withi tn|> 包裹识别结果，CER 计算必须 re.sub(r'<[^<>]*>', '', text) 剥离，否则数字爆炸。
  3. SenseVoice 无 VAD 时间戳分段：segments 只返回 1 段（汇总整段），按时间窗口切 CER 会失真。本轮用"全文对齐"算 CER（更准）。
  4. FunASR 走 modelscope 不走 HF：模型下载走 https://www.modelscope.cn，缓存路径 ~/.cache/modelscope/hub/，与 HF 不同。
  5. pip 默认 stdout 缓冲：Fish Speech 装机脚本（pip install 多个依赖）stdout 不刷，进程看似卡死——必须加 PYTHONUNBUFFERED=1 或 python -u。
  6. openai-whisper SHA256 checksum 不匹配：~/.cache/whisper/small.pt 损坏时会触发自动重下（461MB），进度条只显示到 19% 时被截断 = 被 SIGTERM 杀掉（不是网速问题）。
  7. ChatTTS 模型不在：chattts_generate.py 默认模型路径 ~/voice-tools/models/chattts/2Noise/ChatTTS 不存在，需手动从 HF 下载 2Noise/ChatTTS ~400MB。
  8. Qwen3-TTS 9881 SYNTH_LOCK（沿用上轮）：单槽 + 自旋式 429，并发客户端（SillyTavern）会撞 429。客户端必须重试退避。
