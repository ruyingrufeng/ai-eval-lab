## 决策

1. **TTS 长文路由切 edge-tts**：9882（手动起，proc_9c1fd52aaf1e）→ **待办：写 launchd plist `com.jacky.edge-tts.plist`**。
2. **ASR 默认 small**：改 `~/.hermes/profiles/awei/skills/asr-whisper/SKILL.md` 默认模型从 base → small。
3. **HF 拉取改 hf-mirror + NO_PROXY=***：本机 HTTPS 代理 7892 已死，所有 Python HF 调用必须 unset 代理 + `HF_ENDPOINT=https://hf-mirror.com`。
4. **TTS 评测脚本保留 429 重试退避**：Qwen3-TTS 9881 服务端 SYNTH_LOCK 单槽 + 自旋式拒绝，并发客户端会撞 429。

## 踩坑记录（避免复用）

1. **Qwen3-TTS CustomVoice 100+ 字 padded repetition + 截断**：
   - 100字合成 40.88s 音频（ASR 验证：实际是 40.88s 真实音频 + 内容有重复）
   - 200/500 字也只输出 40.88s（覆盖原文开头约 100字）
   - **结论：CustomVoice 不适合 ≥100 字文本**
2. **本地 HTTPS 代理 7892 已死**：所有 curl/Python 请求走 `HTTPS_PROXY=127.0.0.1:7892` → ConnectionRefused。
   - **对策**：`unset HTTP_PROXY HTTPS_PROXY; export NO_PROXY='*'; export HF_ENDPOINT=https://hf-mirror.com`
3. **Qwen3-TTS SYNTH_LOCK 单槽**：服务端 `if SYNTH_LOCK.locked(): raise HTTPException(429, "TTS is busy; retry later")`。**客户端必须重试退避**，不要假设一次成功。
4. **Hermes Web App 长时间持有 9881**：SillyTavern 自动合成在跑，TTS 评测只能串行+重试，并行会失败。
5. **faster-whisper small 首次 472s 下载**：HF mirror 直连可达但慢；模型缓存后 5-30s 加载。

## 风险与遗留

1. **edge-tts 9882 是手动起的**（proc_9c1fd52aaf1e）：重启机器会丢，必须写 launchd plist 或加自动起逻辑。
2. **Hermes Web App 9881 长期持有**：TTS 评测仍会被串行化，需要 SillyTavern/TTS 用户配合或换评测策略（错峰、跑后台）。
3. **Qwen3-TTS 9881 服务端 SYNTH_LOCK 设计**：建议补 503+Retry-After 退避提示，避免客户端 CPU 浪费。
4. **faster-whisper base 自动繁化**：CER 37.4% 中绝大多数是繁化差异而非字错。如果业务要简体输出，需要后处理加 OpenCC 或 prompt 引导（base 不支持 prompt，改用 small 或后处理）。
5. **ASR 测试样本是 TTS 合成语音**（edge-tts）：与真人语音会有偏差（韵律、口音）。下次需要时可考虑用一段授权真人录音。
