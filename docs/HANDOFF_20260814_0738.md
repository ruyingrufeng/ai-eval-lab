## 项目目标

本项目的目标是评测工具并沉淀最佳使用方法，不是持续做内容创作。本阶段已暂缓以下在线模型能够覆盖的能力：产品图生成、复杂场景与长提示遵循、图片修复与局部编辑、文字排版与封面制作。本轮仅解决本地 Flux 的速度与生产调用方式。

5. 保留历史评测参数和所有旧模型文件，不破坏结果复现。

## 最终决策

### 普通生成默认走 fast

- 模型：`flux1-schnell-Q4_K_S.gguf`
- 步数：4
- CFG：1.0
- 采样器：Euler
- 调度器：simple
- 典型耗时：约 80–100 秒/张
- 用途：构图探索、批量候选、普通环境配图

### 最终成片显式走 quality

- 模型：`flux1-dev-Q4_K_S.gguf`
- 步数：20
- CFG：1.0
- 采样器：Euler
- 调度器：simple
- 典型耗时：约 350–430 秒/张
- 用途：最终人像、身份一致性、复杂物件数量约束、高质量成片

### 身份相关脚本默认保持 quality

`build_flux_ipadapter_workflow()` 新增 `mode` 参数，但默认值是 `quality`。因此服装、多视角、身份一致性和 IP-Adapter 旧调用仍使用 Dev 20 步，不会因为普通生成默认改为 Schnell 而悄悄降质。只有显式传入 `mode="fast"` 才会切换 Schnell。

### 历史评测脚本不改

`run-blind-eval.py`、既有 benchmark 和历史批次内写死的模型及步数继续保留。它们属于可复现实验证据，不是生产默认入口。不要为了“统一配置”批量替换这些固定参数。

## 速度实测

### FLUX.1-dev 参数筛选

| 配置 | 耗时 | 判断 |
|---|---:|---|
| Dev 20 步，768×1024，默认 attention | 350.87 秒 | 生产质量基线 |
| Dev 12 步，768×1024 | 251.29 秒 | 快 28.4%，但明显发虚 |
| Dev 8 步，768×1024 | 174.49 秒 | 快 50.3%，不可交付 |
| Dev 12 步，640×896 | 228.97 秒 | 相对 12 步标准画幅仅再快 8.9% |
| Dev 20 步，split attention | 471.77 秒 | 比默认慢 34.5%，禁用 |

结论：不能靠降低 Dev 步数获得无损提速；不要启用 `--use-split-cross-attention`。

### Schnell 与 Dev 横评

| 场景 | Dev 20 步 | Schnell 4 步 | 提速 |
|---|---:|---:|---:|
| 全身编辑人像 | 350.87 秒 | 79.43 秒 | 4.42× |
| 近景人脸 | 396.26 秒 | 99.53 秒 | 3.98× |
| 复杂宽景 | 426.67 秒 | 89.80 秒 | 4.75× |
| 平均 | 391.27 秒 | 89.59 秒 | 4.37× |

画质判断：Schnell 三个场景均可用，复杂宽景不落下风；近景皮肤更光滑、更有模型感；全身图额外生成一本打开的笔记本，严格物件计数弱于 Dev。因此不全面替代 Dev。

## 默认脚本

### 统一生产入口

```text
scripts/run-flux.py
```

快速档是默认值：

```bash
python scripts/run-flux.py "your prompt" \
  --output /absolute/path/fast.png
```

```bash
python scripts/run-flux.py "your prompt" \
  --mode quality \
  --output /absolute/path/quality.png
```
