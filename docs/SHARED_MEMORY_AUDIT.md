## 时间字段规范

本审计及后续机器可读记录统一保留三类时间：

| 字段 | 含义 |
|---|---|
| 原记录时间 | 原共享记忆条目声明的发生或测试时间；只有日期时标注“精度：日” |
| 最近核验时间 | 最近一次用当前文件、进程、API 或版本重新检查的时间 |
| 入库时间 | 证据被写入本项目索引的时间，不代替原测试时间 |

时间未知时写 `unknown`，不根据文件修改时间或上下文猜测。完整时间化索引见 `registry/shared_memory_evidence.yaml`。

## 共享记忆的价值定位

共享记忆库适合回答：

- 某项工具为何安装；
- 某条路线经历过哪些试验；
- 当时用了什么参数、遇到什么故障；
- 哪些结论后来被新实验推翻；
- 多个 Agent 之间如何交接。

它不应单独用于判断“现在机器上有什么、是否正在运行”。当前状态仍以实时进程、API、文件和版本探测为准。

## 应纳入测试框架的新增项目

1. CosyVoice 对照测试：CosyVoice3-0.5B 与 300M-SFT 的中文可懂度、Whisper 回听和实时系数；先确认是否值得重新下载 SFT 权重。

3. Skill 包审计：只在需要报告、PPT、视频或抖音采集能力时解压到临时目录，检查版本和依赖，不直接安装。
4. 记忆新鲜度检查：自动对比共享记忆里的端口、路径、版本、模型大小与实时探测结果，输出 `current / stale / missing / conflict`。
5. 所有硬件极限结论必须记录测试日期、并发模型、上下文、槽位、KV cache 和 swap，禁止写成无条件“能/不能”。
