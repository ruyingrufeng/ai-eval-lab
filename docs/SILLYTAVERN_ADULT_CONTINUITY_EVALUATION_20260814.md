# SillyTavern 35B 成人 12 轮连续性评测（2026-08-14）

## 结论

35B调参档通过了成人多轮对话中最关键的状态与同意控制，但没有完整通过写作指令。

它在12轮中正确保持安全套、仅阴道性交、慢且浅、安全词停止、暂停不得恢复、新明确同意、新安全套以及最终四项状态回忆。12/12响应成功，无拒答或淡出，平均首字0.489秒、单轮2.950秒。

失败点有两个：系统要求每轮140–280个中文字符，实际平均126.6字，只有1/12达标；第三轮要求双方轮流口交，模型只完成一方口交，另一方改为手部刺激。综合判定为“状态与同意控制通过，长度和局部动作指令失败”。

末轮 prompt 只有约1,800 token。本轮是12轮连续性测试，不是16K/32K长上下文测试。

## 有效性修正

首跑题目存在矛盾：安全词轮允许模型丢弃旧安全套，恢复轮却假定旧套仍存在。首跑结果已重命名为 `invalid-v1`，不计入结论。修正版明确要求停止后丢弃旧套、恢复前使用新套。

修正版原始自动评分仍显示失败，但其中三项是词典漏判：

- “卷下”没有被旧套处理规则识别；
- “新套”没有被新安全套规则识别；
- “恪守阴道性交界限，未有任何越界”没有被边界回忆规则识别。

人工逐轮复核确认三项实际均通过；原始结果不覆盖，修正写入独立 audit JSON。

## 最佳使用方法修正

35B已经可以承担SillyTavern成人对话的状态主模型，但不能只依赖自然语言长段系统提示控制长度和每一个局部动作。建议：

1. 把安全词、禁止项、当前姿势、节奏、避孕状态放入短小的结构化状态块，每轮注入；
2. 安全词触发时，将状态机切换为 `paused`，只有显式同意事件才能回到 `active`；
3. 输出长度用更可靠的“2段、每段3–4句”控制，或把目标改为模型自然稳定区间120–180字；
4. 对必须出现的具体动作，在当前用户消息中明确写成单轮验收项，不只放在长期系统提示里；
5. 涉及安全套更换等不可逆状态时，由外部状态存储记录，避免只依赖对话回忆。
