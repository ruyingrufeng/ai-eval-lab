# 内容增长闭环 Agent 首轮评测（2026-08-14）

HTML主报告：`docs/reports/business_agent_evaluation_20260814/report.html`

## 结论

`Qwen3.6-27B-Fable` 在当前 Hermes Agent + llama.cpp 配置下未通过内容增长闭环，不能作为该工作流的默认 Agent。

第一阶段只要求读取9条固定事实，生成事实表、内容策略和文章提纲。首次运行在600.02秒超时，只完成事实表与内容策略，缺少提纲。保留已有产物后的增量恢复再次在600.03秒超时，仍缺少提纲，并且模型重复改写了已经完成的事实表。外部 grader 两次均判失败，后三阶段按照止损规则没有运行。

这不是中文理解完全失败：已有事实表覆盖9/9来源事实，没有发现编造；内容策略对受众、信息优先级、试运营边界和反夸张写法的处理基本可用。失败集中在 Agent 的任务推进、完成性、增量恢复和延迟。

## 评测任务

本轮使用同一个“澄湾城市生活”案例，完整工作流原计划包含：

1. 资料理解与内容策略；
2. 公众号文章初稿与按意见改稿；
3. 历史内容运营数据计算与复盘；
4. 下一轮四条内容实验计划。

每阶段最多600秒；任一阶段超时即停止，避免为已经不具备实用性的路线继续消耗时间。

## 结果

| 运行 | 时间 | 完成产物 | 缺失产物 | 判定 |
|---|---:|---|---|---|
| 首次 | 600.02秒 | 事实表、内容策略 | 提纲 | 超时失败 |
| 增量恢复 | 600.03秒 | 事实表、内容策略 | 提纲 | 超时失败 |

完整工作流阶段通过数为0/4。两次累计可观测 Agent 时间为1,200.05秒；写作改稿、运营分析和闭环计划均未进入，不能评价这些阶段的27B内容质量。

## 内容复核

### 可用部分

- 9条来源事实全部保留；
- 没有把8周试运营写成永久服务；
- 受众拆分合理，覆盖通勤者、游客和家庭/行动不便乘客；
- 信息优先级正确，先时间、区域和票价，再换乘、无障碍和小程序；
- 明确拒绝无证据的“必火”“必排队”等夸张表达。

### 不可用部分

- 三个必需文件始终缺一个，无法进入下一阶段；
- 超时后没有 usage 文件和最终答复，Agent 未正常收尾；
- 增量恢复没有优先补缺，而是重写已完成的事实表；
- 简单资料整理阶段两次均超过10分钟，不符合日常内容工作的交互效率。

## 最佳使用方法判断

当前证据只支持“27B具备一定的资料理解与内容策略质量”，不支持“27B适合独立执行内容增长 Agent”。如果继续使用该模型，应把任务压缩为单一直接生成调用，由外部编排器明确控制每一步和文件写入；但这种拆分路线尚未在本项目正式验证，不能进入默认推荐。

本轮不通过并不等于否定27B的纯写作能力。纯写作、数据解释和方案质量需要在更快、更确定的调用方式下另行评测；本轮否定的是当前完整 Agent 路线。

## 下一步与停止条件

下一候选模型先只跑第一阶段闸门：

- 必须生成事实表、策略和提纲三项；
- 9/9事实保留且无编造；
- 180秒内完成并正常退出；
- 恢复任务必须优先补缺，不得无意义重写已完成产物。

只有通过该闸门，才允许继续完整内容增长闭环。

## 30B / 35B 独立配置闸门补测

已为30B和35B建立不影响内容生成默认服务的独立 Hermes 配置，并分别启动专用 llama.cpp 服务。30B模型训练上下文实际把服务槽位限制在40960；35B成功建立65536槽位。

| 模型 | 闸门时间 | 三项文件 | 9项事实 | 正常退出 | 严格判定 |
|---|---:|---|---|---|---|
| 30B | 180.010秒 | 齐全 | 通过 | 否 | 失败 |
| 35B | 180.007秒 | 齐全 | 通过 | 否 | 失败 |

两者都在超时前生成了 grader 可识别的三项文件，但 Hermes 持续调用工具，没有返回最终答复，进程以124超时退出。因此不能因为“文件已经存在”就宣告 Agent 可用。35B的策略与提纲最完整，包含必需的“出发前检查清单”；30B产物较浅，并漏掉该检查清单。该差异说明35B语言质量更好，但当前阻塞首先是 Agent/Hermes 完成协议与工具循环，而不是继续扩大模型参数。

严格结论：27B、30B、35B 均不进入完整业务 Agent 默认路由。下一步应先修正或替换编排方式，让 Agent 在文件完成后验证并退出，再用同一180秒闸门复测；闸门通过前不跑后三阶段。
