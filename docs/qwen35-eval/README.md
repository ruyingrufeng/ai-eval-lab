# Qwen3.5-9B 本地 Agent 独立评测方案

## 一、评测目标

评估 Qwen3.5-9B 是否适合作为本地长期运行的 Agent 模型。

重点不测试传统知识问答或 benchmark，而测试真实 Agent 工作所需能力：

- 复杂语义理解
- 多条件指令保持
- Tool Calling
- 多步骤任务规划
- 工具结果理解
- 异常恢复
- 事实核验与抗幻觉
- 长任务目标保持
- 长上下文稳定性
- 执行效率
- 本地资源占用

最终判断：

> 模型是否具备作为日常本地 Agent 的可靠性、速度和上下文能力。

---

# 二、测试环境

## 模型

`Qwen3.5-9B-Q4_K_M`

## 推荐基础配置

- llama.cpp / llama-server
- Metal 全量 GPU offload
- Slot：1
- Context：131072
- KV Cache：优先 Q8_0 / Q8_0
- reasoning：关闭
- temperature：0.6 左右
- top_p：0.9 左右

如果 128K + Q8 KV 出现明显内存压力，再测试：

`K = Q8_0 / V = Q4_0`

测试过程中不要随意修改配置，保证结果可比较。

---

# 三、核心测试原则

所有任务必须满足：

1. 不人工提示下一步
2. 不人工纠正模型
3. 工具报错后由模型自主处理
4. 不因为模型走错就提前终止
5. 完整保存 Agent 日志
6. 最终结果必须独立验证
7. 成功运行程序不等于任务成功
8. 所有数值结果必须与真实数据核对

重点观察：

> 模型能否自己把事情做完，而不是“看起来会调用工具”。

---

# 四、测试项目

## T1｜基础工具闭环

### 目标

验证最基本的：

`理解任务 → 调用工具 → 创建文件 → 执行 → 读取结果 → 返回答案`

### 任务

要求 Agent：

1. 创建 Python 脚本
2. 计算 1～100 的平方和
3. 执行脚本
4. 读取运行结果
5. 返回最终数值
6. 保留脚本文件

### 验证重点

- 是否正确创建文件
- 是否真正执行
- 是否读取工具结果
- 是否得到正确答案
- 是否凭模型自己计算后假装运行

---

# T2｜多约束任务保持

### 目标

测试连续执行中是否会遗忘条件。

### 任务设计

准备一个 CSV 数据集。

一次性提出至少 8 条约束，例如：

1. 只处理指定年份
2. 排除某一类别
3. 数值为空的记录不能参与计算
4. 按金额降序
5. 只保留前 10 项
6. 输出 JSON
7. 原 CSV 不能修改
8. 结果保存到指定目录

### 验证

逐项核对 8 个条件。

记录：

`约束保持率 = 正确保留条件 / 8`

评价：

- 8/8：优秀
- 7/8：合格
- ≤6/8：Agent 使用风险较高

---

# T3｜事实一致性 / 不编造

### 目标

测试模型面对“找不到答案”时是否 hallucinate。

### 任务

在一个员工数据文件中，故意查询一个不存在的人：

> 找出“钱七”的年度销售额，并分析他的表现。

正确行为：

1. 搜索数据
2. 没有找到
3. 检查是否存在类似名称
4. 明确告诉用户记录不存在
5. 不生成虚构销售数据

### Fail 条件

出现任何不存在的数值、记录或事实。

---

# T4｜工具成功，但结果错误

### 目标

测试模型是否具有 sanity check 能力。

### 测试设计

准备一个 Python 脚本：

- 能正常运行
- exit code = 0
- 输出看起来合理
- 但计算公式故意写错

例如：

正确：

`variance = sum((x-mean)^2) / n`

故意改成：

`variance = sum((x-mean)^2) / 2`

### 给 Agent 的任务

> 检查这份数据的平均值和方差是否正确，如果有问题就修复，并给出验证结果。

### 关键观察

模型是否：

`程序成功 → 直接相信`

还是：

`程序成功 → 检查逻辑 → 独立核算 → 发现错误 → 修复`

这是 Agent 智力的重要分水岭。

---

# T5｜噪音文件干扰

### 目标

测试语义判断，而不是文件名匹配。

### 目录设计

同时放入：

- `sales.csv`
- `sales_final.csv`
- `sales_draft.csv`
- `sales_old.csv`
- `sales_backup.csv`
- `sales_2024.csv`
- 一个文件名正确但内容错误的文件

要求：

> 找出当前正式销售数据并计算平均订单金额。

### 观察

是否会：

- 打开多个候选文件
- 根据内容判断
- 根据日期/字段/数据一致性判断
- 排除 draft / old / backup
- 对异常数字产生怀疑

Fail：

> 直接使用第一个看起来像正确文件的结果。

---

# T6｜误导性文件名

### 目标

测试模型是否被表面语义误导。

### 示例

创建：

`login_config.json`

但文件实际内容：

```json
{
  "payment_gateway": "...",
  "currency": "USD",
  "refund_policy": "..."
}
```

任务：

> 找到认证系统的配置文件并告诉我使用的认证方式。

### 合格行为

模型打开文件后发现：

> login_config.json 实际不是认证配置。

然后继续搜索。

### Fail

根据文件名直接把 payment 配置当成 login 配置。

---

# T7｜失败恢复

### 目标

测试真实环境变化下的自主调整能力。

### 任务

告诉模型：

> 请读取 `sales_2025_final.csv`，计算销售总额。

但这个文件不存在。

目录存在：

`sales_2025.csv`

以及一些无关文件。

### 观察

是否：

1. 尝试读取
2. 收到 file not found
3. `ls`
4. 分析替代文件
5. 打开并验证内容
6. 继续完成任务

Fail：

- 不断重复读取不存在的文件
- 直接放弃
- 编造结果

---

# T8｜任务中途改变目标

### 目标

测试动态任务状态管理。

### 第一阶段

要求：

> 清洗订单数据，过滤无效记录，并输出 CSV。

Agent 开始执行后，再追加：

> 输出改成 JSON，但之前的筛选规则全部保持不变。

### 检查

- 是否正确切换 JSON
- 是否保留原筛选条件
- 是否重新从头乱做
- 是否丢失已确认约束
- 是否产生错误版本

---

# T9｜隐式约束长期保持

### 目标

检测 Agent 工作记忆。

### 第一轮明确要求

> 整个任务只允许分析 2025 年的数据。

之后不要再重复。

让 Agent 连续完成：

1. 数据查找
2. 清洗
3. 分类
4. 统计
5. 生成脚本
6. 执行
7. 分析结果
8. 输出报告

至少经过 8 次工具调用。

最后检查：

> 是否偷偷混入其他年份。

---

# T10｜10+ Tool Calls 长链路

### 目标

测试长程 Agent 稳定性。

任务必须自然产生至少 10 次工具调用。

推荐流程：

`查找文件`
→ `读取数据`
→ `检查格式`
→ `生成程序`
→ `执行`
→ `发现异常`
→ `修改程序`
→ `重新执行`
→ `独立验证`
→ `写结果`
→ `重新读取`
→ `最终确认`

### 记录

- 总 tool calls
- 有效 calls
- 重复 calls
- 无意义 calls
- 错误 calls
- 最终是否完成

特别关注：

> Agent 是否随着任务变长越来越混乱。

---

# T11｜模糊意图理解

### 目标

专项测试语义理解。

不要给步骤。

只告诉模型：

> 帮我看看这个目录里的销售数据，找出今年真正有效的数据，分析一下销售情况有没有明显异常。不要修改原始文件。

目录故意设计得复杂。

模型需要自行判断：

- 哪个文件有效
- 哪个年份属于“今年”
- 什么数据值得分析
- 什么属于异常
- 是否需要脚本
- 如何验证

### 评价重点

不是工具调用次数，而是：

> 是否真正理解用户想解决的问题。

---

# T12｜冲突条件理解

### 任务

给出：

> 不允许修改任何原始数据文件。把清洗后的数据保存到原目录。

这两个要求并不真正冲突。

正确理解：

> 原文件只读，在相同目录创建新文件。

测试模型能否正确解释自然语言，而不是机械执行。

- 约 16K
- 约 32K
- 约 48K
- 约 64K
- 约 96K
- 约 120K

**16K / 32K / 64K / 96K**

如果 96K 仍稳定，再测 120K。

2. 保持早期约束
3. 使用工具完成计算

# 六、128K 实用性测试

# 九、Agent 通过标准

## 推荐作为本地主力

同时满足：

- Agent Intelligence ≥18/20
- 核心测试成功率 ≥85%
- T3、T5、T7、T8 必须通过
- 严重 hallucination = 0
- 64K 上下文稳定
- E2E 时间达到实际可用水平
- 长链路不会明显目标漂移

## 推荐作为轻量 Agent

如果：

- 简单任务稳定
- 速度快
- 但复杂异常恢复或长链路能力下降

可以定位：

> 文件操作、自动化、小型 coding、简单数据处理。

## 不推荐做 Agent 主力

出现以下任一情况：

- 高频 hallucination
- 工具报错后无法恢复
- 多条件频繁丢失
- 长链路目标漂移明显
- 32K 后语义能力明显崩溃
- 反复执行相同失败操作

## 最重要的评测原则

整个评测始终围绕三个问题：

> **它懂不懂我要干什么？**

> **环境出问题以后，它会不会自己解决？**

> **任务做长以后，它还记不记得自己为什么在做这件事？**

这三个问题，比任何传统 benchmark 分数都更接近真实 Agent 能力。
