## Qwen3.8 长程 Agent 实测结果（本轮新增关键证据）

### 测试设计

- 模拟 Hermes 工具循环：`scripts/benchmark-qwen38-agent-longrun.py`；
- 任务：读 A/B 两份测试统计 → compare 对比 → write_report 写报告 → 总结，5 步真实工具调用；
- 工具 schema：read_stats / compare / write_report，tool_choice=auto，max_tokens 1024，temp 0.5；
- 每轮真实执行工具、结果回填 messages，上下文逐步累积；
- 原始结果：`results/agent_longrun_20260815/qwen38_agent_longrun.json`。

### 失败链路（12 轮，全记录）

| 轮 | 动作 | 结果 |
|---|---|---|
| R1 | read_stats ×2（并行两个文件） | ✅ 24.5s，参数标准 |
| R2 | compare（传两个完整 JSON） | ❌ 参数被截断 → JSONDecodeError |
| R3–R12 | 重试 compare（同样截断错误） | ❌ 连续 10 轮完全相同失败，从不改策略 |
| — | write_report | ❌ 从未被调用，报告未产出 |

### 失败模式定性（与 27B 对照）

- 27B 的病（上轮已知）：600s 超时 + 产物不完整；
- 3.8 的病：**单步 tool calling 过关（08-15 4 步链 read→calc→save→总结全对），但长程多步下：① 生成大参数时被 max_tokens 截断；② 遇到错误不自适应——10 轮重试完全相同的坏参数，从不简化参数、不分步、不换路；③ 上下文累积后变慢（R2 46s → R6 59.5s）。**
- 结论：**本地模型做完整自主 Agent 路线仍不推荐；Hermes 继续云端 DeepSeek；3.8 不进 Agent 路由。**
- 注：compare 工具设计（要求传两个完整 JSON 约 1.5KB）放大了截断问题，但"失败后死循环重试同一错误"是模型行为缺陷，与工具无关，不因测试设计弱化。
