# 阶段性总结：图片链路已形成最佳实践，项目整体进入跨类型补齐阶段

## Executive Summary

- **阶段目标部分达成。** 项目的核心目标是“评测工具并沉淀最佳使用方法”。图片通用生成已经完成从候选发现、安装、本机运行、质量/速度评测到默认 CLI 的闭环；整个多模态工具项目尚未完成。
- **图片主线已达到可交接状态。** 本机形成 `fast`（FLUX.1-schnell 4 步）与 `quality`（FLUX.1-dev 20 步）双档；Schnell 三场景平均 89.59 秒，Dev 平均 391.27 秒，快速档平均提速 4.37 倍。
- **本地通用参考图身份链已完成并终止。** 高质量三母版有效，但 Flux IP-Adapter 无法兼顾身份与全身；普通 Flux 底图 + InSwapper 的三个换脸结果相似度仅 0.0774–0.1186、视觉 0/3。精确身份改走角色 LoRA 或在线身份编辑。
- **下一阶段不再扩展图片内容题材。** 优先完成默认 CLI 冒烟、Schnell 候选到 Dev 精修的编排，再把主要时间转向文本、TTS 和程序化视频的正式统一基准。
- **语言模型路由已按实际内存重新收拢。** 本地27B/30B/35B均不用于Hermes，Hermes继续走云端；35B因约21.2GiB RSS且不能与7B视觉模型可靠共存退出实际路由，30B因约40K上下文退出。27B从双槽改为单槽64K，只供SillyTavern；历史双槽与35B短任务结果保留为证据，不再代表生产默认。

## 本阶段最重要的工具结论

### 图片生成已经形成可执行的双档策略

普通生成默认使用 Schnell 4 步，最终人像、复杂物件和身份任务使用 Dev 20 步。快速档并非低质量草稿：三类代表场景均可用，但在人脸自然度和物件计数上仍弱于 Dev。

### 继续压缩 Dev 步数不是有效优化方向

Dev 12 步虽然快 28.4%，但画质明显发虚；8 步虽然快 50.3%，但不可交付。`split attention` 比默认实现慢 34.5%，明确禁用。常规启动使用默认 RAM pressure cache，不使用 `--cache-none`。

### 身份一致性不能用“继续堆权重”解决

单阶段 IP-Adapter、高质量三母版和两阶段 InSwapper 均未过线。IP-Adapter 会生成稳定的相近角色，但不能兼顾指定身份与全身；InSwapper 在全身小脸上产生明显五官变形，三个结果视觉 0/3。通用参考图路线到此止损，不再继续堆权重、放大或重复换脸。

### 项目没有滑向内容创作

所有生成样张均服务于固定评测问题；产品图、复杂场景、修图、排版和封面等在线模型已能覆盖的能力已主动暂缓。下一阶段继续以固定案例、硬门槛和停止条件为中心，不以内容数量作为成果。

## 下一阶段计划

### P1A：语言模型 Agent 工具链冒烟（已完成，业务基线待测）

1. 新增三类真实 Agent 任务：代码修复、受约束仓库维护、证据型报告；全部在独立沙盒中由外部 grader 判分。
2. Qwen3.6-27B-Fable 首次 2/3，通过任务分别耗时 246.71 / 304.75 秒；证据报告 600 秒超时。修正规则后重试可通过，但耗时 555.06 秒。
3. 口径修正：以上只验证技术工具链，不能外推自媒体写作、运营分析、调研、方案、PPT 与访谈分析能力。
4. 30B 只有一个有效失败样本；另两题因当前 16K 上下文低于 Hermes 64K 要求未测。下一步先建立独立 64K Agent 服务，再测 30B/35B。
5. 业务用途最终收拢为内容增长、研究到决策、访谈到洞察三条工作流。首批用同一案例串联写作、运营分析和下一轮计划，控制在一小时；计划见 `docs/AGENT_BUSINESS_EVALUATION_PLAN_20260814.md`。
6. 内容增长闭环27B首测已止损：第一阶段首次与恢复均600秒超时，阶段通过0/4；已有资料策略内容可用，但Agent推进与效率不合格。报告见 `docs/CONTENT_GROWTH_AGENT_EVALUATION_20260814.md`。

### P0：封闭图片工具链（已完成）

1. `run-flux.py` 的 `fast` / `quality` 端到端冒烟已通过。
2. Schnell 连续 10 张 10/10 生成成功，候选合格 9/10；p50 75.41 秒，p95 105.63 秒。
3. 同 seed、整图参考、人脸裁剪、高质量三角度身份母版均已完成验证。
4. 图片通用生成主线冻结；精确身份的通用参考图分支也已关闭，未来只考虑角色 LoRA 或在线身份编辑。

### P1：文本与语音建立正式基线（进行中）

1. Agent：本地27B/30B/35B均退出Hermes；Hermes继续使用云端模型，不再为本地模型扩展业务Agent测试。
2. SillyTavern：35B调参档已通过五轮基线；下一步验证16K/32K记忆、世界书优先级、边界与跨会话状态。
3. 根据这些结果，再决定是否补 MLX 7B–14B 快速档；没有决策价值就不下载。
4. TTS：Qwen3-TTS 跑短句、长段落和连续请求；记录首包、实时系数、可懂度、音频伪影和模型加载成本。
5. ASR 只做支持 TTS 评测所需的回转录基线，不扩展成独立内容项目。

### P2：程序化视频闭环（预计 1 天）

1. 固定 3 个中性 3–5 秒案例，分别由 HyperFrames/Remotion 渲染。
2. 验收确定性渲染、旁白长度、字幕同步、FFmpeg 封装和 CLI 可复现性。
3. 只在程序化链路通过后，才执行 LTX-Video MPS 单个 3 秒低分辨率冒烟；触发内存或效率止损即停止。

### P3：数字人只在前置条件满足后恢复

必须同时具备：同一目标角色的正脸、3⁄4脸、侧脸母版；授权或合成声音；图片、TTS 和包装链路已通过。随后才测 LivePortrait/MPS、口型误差和端到端导出。MuseTalk 继续保持 CUDA 不优先。

## 阶段验收标准

下一阶段结束时应满足：

- 图片：统一 CLI 实跑通过，Schnell 连续 10 张稳定，候选→精修脚本可复现；
- 文本：至少一套质量档和一套可接受的快速档有正式报告；
- TTS：至少一个中文旁白方案完成速度、可懂度和稳定性验收；
- 程序化视频：至少一个可复现 CLI 完成 3 个固定案例；
- 所有结论同步到注册表、决策日志和交接文档；
- 未通过项明确记录阻塞条件，不以“可以运行”冒充“已经验证”。

## 局限与假设

- Schnell 与 Dev 横评只有 3 个场景；它支持工作流分档，但不支持“全面替代”的结论。
- 身份一致性仍只有两个正式确认 seed，但已使用高质量正脸、3/4、侧脸母版；足以否定当前 Flux IP-Adapter 精确身份全身路线，不能外推否定角色 LoRA 或两阶段局部身份替换。
- SillyTavern只完成五轮中性成年角色基线，不能外推为长篇小说、超长记忆或所有边界场景通过；Agent失败也不能外推为纯写作质量失败。
- TTS、视频部分引用的是安装盘点和历史项目证据，尚未完成本项目统一验收，因此统一标为待验证或部分完成。
- 本报告不计算跨内容类型总分；不同内容类型的硬门槛不同，把它们加权为单一百分比会制造虚假精度。
